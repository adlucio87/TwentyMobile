# 🛡️ TwentyMobile Security & Network Traffic Audit

**Document Version:** 1.0  
**Date:** September 2026  
**Audited Targets:** TwentyMobile v1.13 through v1.0.16 (`com.luciosoft.pocketcrm`)  
**Tested Against:** Twenty CRM v2.42.6 (Self-Hosted Instance)  
**Methodology:** Full runtime network egress capture via local logging proxy (MITM TLS decryption, DNS query logging) combined with static Dart/Flutter and native iOS/Android source code audit.

---

## 1. Executive Summary

TwentyMobile is an open-source Flutter client for **Twenty CRM**. The primary design goal for self-hosted users is **data sovereignty**: CRM records, customer information, tasks, and media must stay strictly between the mobile device and the user's self-hosted server.

### Key Audit Conclusions:
- **Core CRM Traffic:** All CRM operations (contacts, companies, custom objects, tasks, notes) communicate directly and exclusively with the user-configured Twenty server over GraphQL and REST endpoints.
- **No Third-Party Analytics or Trackers:** The app contains **zero** commercial advertising SDKs, marketing trackers, or behavior analytics platforms (no Google Analytics, Firebase Analytics, PostHog, Mixpanel, or Amplitude).
- **Local-First Notifications:** Push notifications are scheduled **100% locally** via the device OS alarm/notification system (`flutter_local_notifications`). No third-party push gateway (FCM, APNs relay, OneSignal) is employed.
- **On-Device Machine Learning:** Both Business Card OCR scanning and Speech-to-Text dictation process data directly on the mobile hardware.
- **Privacy Hardening (v1.0.16):** Community-driven hardening (via PR #49) introduced zero-PII error reporting, an opt-out toggle, and guaranteed on-device speech recognition.

## 3. Detailed Audit Findings & Hardening History

### 3.1 Error Reporting & Sentry/GlitchTip
* **v1.13 Behavior:**
  * Crash reports were sent unconditionally in release builds to `app.glitchtip.com`.
  * Events carried `user.id` containing the installation ID generated by the Sentry SDK.
  * Standard SDK integrations attached up to 77 breadcrumbs (screen transitions, keyboard appearances, screenshots, and internal console logs).
  * Server validation failures in GraphQL operations attached the raw `OperationException`. If Twenty CRM echoed user-submitted field values in a validation error, those values were included in the error payload.
  * An initial DNS lookup for `sentry.io` occurred on iOS during native Cocoa SDK startup prior to custom DSN evaluation.
* **v1.0.16 Hardening:**
  * **User Opt-Out Toggle:** Added **Settings → Privacy → "Send crash reports"** switch. Disabling it skips Sentry SDK initialization entirely.
  * **Compile-Time Elimination:** Compiling with `--dart-define=ERROR_REPORTING=false` completely strips error reporting from the build, eliminating all network traffic and DNS queries to Sentry/GlitchTip.
  * **Content-Free Error Reports:** GraphQL exceptions are stripped of record data and replaced with a `GraphQLFailure` summary containing only HTTP status and error codes (e.g. `graphql=[UNAUTHENTICATED] link=ServerException`).
  * **Data Scrubbing:** Stripped `event.user` (no installation ID), dropped all console log breadcrumbs, and disabled native UI breadcrumbs (`enableAutoNativeBreadcrumbs = false`).

### 3.2 Voice Notes & Speech Recognition
* **v1.13 Behavior:** Voice transcription invoked `speech_to_text` without `onDevice: true`, prompting iOS to stream audio to Apple's dictation infrastructure (`guzzoni.apple.com`).
* **v1.0.16 Hardening:** Enforced `SpeechListenOptions(listenMode: ListenMode.dictation, onDevice: true)`. Audio processing is performed exclusively by on-device neural engines. If offline speech recognition is unsupported by the OS for a given language, the app surfaces a localized message rather than falling back to remote servers.

### 3.3 Business Card Scanner (OCR)
* Optical Character Recognition is executed on-device using `google_mlkit_text_recognition` with Latin script models.
* Image bytes and extracted contact details never leave the device.
* Google ML Kit transmits background SDK usage telemetry to `play.googleapis.com`.

### 3.4 Offline Typography & Local Assets
* Inspection revealed that font files in `google_fonts/` were corrupted web HTML preview pages rather than binary TrueType fonts.
* Because `allowRuntimeFetching = false` was set, the app fell back to system typography without contacting Google Fonts CDN.
* **Resolution (v1.0.15):** Replaced with authentic static TTF binaries of the Inter font family across all weights (100–900). Typography renders offline with zero network egress.

### 3.5 Demo Mode & API Key Architecture
* The "Try Demo" mode connects to `twentycrm.luciosoft.it` using a bundled API token with `exp: 4928029264` (the 100-year timestamp assigned when selecting "Never expires" in Twenty CRM).
* **Upstream Twenty CRM Constraint:** In Twenty CRM, API keys are forced to the `Admin` role by default; non-admin API key roles are not yet supported upstream.
* **Client-Side Guard:** TwentyMobile enforces mutation locks in the client (`DemoUtils.checkDemoAction` and `if (isDemo) throw Exception(...)`).
* **Roadmap Plan:** Migrate the demo mode to authenticate against a dedicated restricted user account (`Member` role) via email/password or ephemeral tokens to retire the static API key.

## 4. Hardening Recommendations for Self-Hosted Deployments

For organizations requiring strict data isolation, zero telemetry, or air-gapped operation:

### 1. Completely Disable Error Reporting at Build Time
Build the client with the compile-time flag:
```bash
# Android
flutter build appbundle --release --dart-define=ERROR_REPORTING=false

# iOS
flutter build ipa --release --dart-define=ERROR_REPORTING=false
```
*Effect:* Completely omits GlitchTip/Sentry initialization. Zero outbound connections or DNS lookups.

### 2. Runtime Opt-Out via Settings
If using standard store builds:
1. Open **Settings**.
2. Scroll to the **Privacy** section.
3. Toggle off **Send crash reports**.
4. Restart the app.

### 3. Prevent External CAPTCHA Calls
In your self-hosted Twenty instance configuration:
* Ensure Turnstile and Google reCAPTCHA are not configured in your Twenty server environment variables.
* The mobile client queries `GET /client-config` at login. When `captcha` is absent, the app initiates zero third-party webview connections.

## 5. Verification & Testing

This audit can be independently reproduced using any standard MITM proxy:
1. Install and trust a proxy root certificate (e.g. `mitmproxy`, Charles Proxy, Proxyman) on a test iOS or Android device.
2. Configure the device Wi-Fi proxy to point to the logging host.
3. Launch TwentyMobile and perform typical workflows (login, contact browsing, card scanning, voice dictation).
4. Verify all request logs against the table in **Section 2**.
